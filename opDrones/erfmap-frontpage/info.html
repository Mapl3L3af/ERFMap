01 / IN THE FIELD

Give every surface more than one view.

Plan the coverage

Fly at any steady height that keeps the ground sharp, with the camera looking straight down; erfMap adapts to each flyover from its measured scale. Aim for 80% forward and 70% side overlap on steady, parallel passes, then a crossing pass. Keep clear of obstacles; height above takeoff may differ from height above the ground. Keep the ground in view and extend the capture beyond your area of interest. Include connecting images between separate parts of the site.

Keep detail sharp

Use good, even light. Move slowly, avoid sudden turns and keep exposure consistent. Check that paths, roof edges and vegetation remain sharp before leaving. Preserve the original photos or video.

Measure on the ground

Record a clearly visible, long ground distance. Select the same endpoints during scale calibration. Multiple independent distances help reveal scale disagreement. A known length alone does not determine vertical orientation.

Overhead imagery suits the current planar map. A full building reconstruction also needs overlapping oblique views of its sides and a separate photogrammetry engine. Unseen walls and ground beneath vegetation cannot be recovered from the overhead image alone.

02 / THE WORKFLOW

Review before you redesign.

  1. Upload. Add one video or a set of overlapping photographs in New Flyover. Original files stay with the job.
  2. Check coverage. Inspect sharpness, matching groups and overlap warnings. Disconnected imagery may need another flight.
  3. Set scale. Mark both ends of a known distance on the assembled image and enter its measured length. Latitude, longitude and height fields are in this same measurement panel.
  4. Review zones and objects. Correct buildings, grass and paths, then benches, lights and trees. Accept or reject proposals and confirm scene-edge access.
  5. Open the survey. Edit geometry and properties, inspect the plan, measure distances and walk through the 3D scene.

Classification confidence is model evidence, not a guarantee. Check every proposal against the original imagery. Simulated pedestrian activity is a design aid, not a measured forecast.

03 / DEPTH WITH EVIDENCE

Terrain and contours share one ground model.

The built-in image workflow creates a planar map. A local NodeODM service can supply an SfM reconstruction when configured. To obtain measured relative heights, process overlapping imagery with a reconstruction engine, establish scale and vertical orientation, filter ground points, and register the resulting ground grid to the map.

Bring in ground data

Use File → Import ground grid in a survey. Supply heights in metres at a regular grid registered to the local map. Use null for missing data. Complete cells become terrain triangles; holes stay open.

Inspect contours

Use Settings → Show contours and set the contour spacing in metres. Under Analyse → Elevation map, select two points for an elevation profile. Profiles crossing gaps report missing observations.

Export the result

Download contours in local metre coordinates or a terrain-aware GLB from the File menu. Contours are relative to the supplied vertical datum. The files do not imply a GPS position or survey-grade accuracy.

Ground grid JSON format

Example: a 10 × 10 metre observed patch, with four ground heights. Adjust origin and spacing to match your survey; do not invent elevations.

{
  "format": "erfmap-ground-grid-v1",
  "units": "metres",
  "source": "Your ground survey or reconstruction method",
  "datum": "Relative to the measured reference point",
  "groundGrid": {
    "origin": [0, 0],
    "step": [10, 10],
    "heights": [[0, 1], [0.5, 1.5]]
  }
}

Rows increase along map y; columns increase along map x. Grid size is 2–256 rows and columns. All cells must fall within the survey extent. A cell needs all four corner observations to be modeled.

04 / KEEP YOUR WORK MOVING

Save, reopen, collaborate.

  • Scenario JSON: editable features, ground samples, terrain, contours and provenance. Download a backup from the survey.
  • erfMap GLB: a 3D model with embedded editable survey data. Reopen it through Open Project or Import survey. Arbitrary third-party GLBs cannot be converted into editable survey features.
  • Contours JSON: line segments, heights, interval and source in local metre coordinates; not geographic GeoJSON.
  • Project code: share the server address and four-digit code with up to four editors. Anyone with server access and the code can edit. Keep the server running.
05 / PROCESSING & RECOVERY

Know what is ready.

Checking local processing tools…

    Python, NumPy, OpenCV and Pillow support image processing. FFmpeg and ffprobe handle video. Optional classifiers propose labels. Install worker dependencies in the project’s Python environment; the Processing setup panel in intake shows missing tools.

    Reconstruction integration

    Set ERFMAP_NODEODM_URL to a running NodeODM service (for example http://127.0.0.1:3001), or set ERFMAP_RECONSTRUCTOR to a custom adapter, then restart the server. Retry Image correction on a stitched job to build an ODM orthophoto before calibrating and labeling; review those downstream steps again. Separate-photo sheets keep their existing workflow. The worker validates metre scale, vertical alignment, ground filtering and mosaic registration before using its output. See worker/README.md for the adapter contract. This setting does not install an engine.

    A stage stopped or failed

    Read its error, resolve missing tools or improve the input, then retry that stage. Later stages and their review decisions are rebuilt. After a server interruption, retry the interrupted stage. Back up downloaded scenarios and the server’s project data before moving machines.

    06 / OPTIONAL PHOTOGRAMMETRY

    Set up a building reconstruction.

    The standard map workflow works without a reconstruction engine. For photogrammetry, open Optional · Photogrammetry setup before uploading photos. Existing flyovers have the same setup in the measurement panel, reached through Source imagery → Map reference.

    Capture roofs and sides

    Keep the overhead photographs and add overlapping angled photographs around the building so each wall, roof edge and corner appears from several positions. OpenDroneMap recommends a cross-grid at about a 45° camera angle with 70–80% overlap for full 3D work, alongside overhead coverage. Keep exposure consistent and retain the original photos. Three photos is only the engine’s minimum input count, not enough coverage for a typical building.

    Official capture guidance ↗

    Start the engine

    Install Docker, then run NodeODM on a machine with enough memory and disk space for your photo set. A local example uses port 3001 so erfMap can keep port 3000:

    docker run -d --name erfmap-nodeodm -p 127.0.0.1:3001:3000 -v erfmap-nodeodm-data:/var/www/data opendronemap/nodeodm

    Install worker/requirements.txt in erfMap’s Python environment; the terrain adapter requires rasterio. Larger photo sets take more memory, storage and processing time.

    Official NodeODM setup ↗

    Connect the flyover

    Enable Use NodeODM for this flyover, enter http://127.0.0.1:3001 for a service on the erfMap server’s machine, then select Check connection. If the engine runs elsewhere, use its reachable address. Select Request a full 3D building model when your photos include the sides. Upload the original photographs together; the selected service receives them when processing starts.

    1. Review capture checks. Sharpness and planar overlap checks cannot prove that every building side is covered. Angled views are allowed for photogrammetry; missing surfaces need additional photos.
    2. Calibrate and review. NodeODM builds an orthophoto before measurement and labeling. Confirm the scale and review the features again. Changing setup on an existing flyover rebuilds imagery, calibration and review decisions.
    3. Get the engine outputs. After reconstruction, open Source imagery and download Photogrammetry files (ZIP). A requested building model is retained in that archive when the engine successfully produces it.

    erfMap currently uses the reconstructed orthophoto and ground terrain. Detailed walls, roof meshes and photographic textures are available in the engine’s output files for an external 3D viewer; they are not imported into erfMap’s editable survey or its feature-based GLB. The setup does not verify facade completeness or turn estimated building heights into measurements.
